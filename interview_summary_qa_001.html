Java Core

Вопрос: Какие типы данных есть в Java?

Ответ: Примитивные (8 штук: byte, short, int, long, float, double, char, boolean) и ссылочные (объекты, массивы). Примитивы хранятся в стеке (локальные переменные) или как поля объекта, ссылочные типы — в куче, переменная содержит ссылку.

📖 Подробнее про типы данных и память

Примитивы: byte (1 байт), short (2), int (4), long (8), float (4), double (8), char (2, Unicode), boolean (в массивах 1 байт, вне массивов зависит от JVM).

Ссылочные типы (Reference Types): Классы, интерфейсы, массивы, перечисления (enum). Переменная такого типа хранит ссылку (адрес) на объект в куче (Heap).

Память:

  • Стек (Stack): Быстрый, потокобезопасный, хранит локальные переменные и ссылки.
  • Куча (Heap): Общая для всех потоков, хранит объекты, очищается Garbage Collector.

Вопрос: Зачем нужны классы-обёртки?

Ответ: Для использования примитивов в коллекциях и дженериках, доступа к полезным методам (parseInt, toString, константы), а также для представления отсутствия значения (null).

📖 Подробнее про обёртки и Autoboxing

Причины использования: Дженерики (List<Integer>) не работают с примитивами. Методы: Integer.parseInt("123"), Integer.MAX_VALUE. Возможность передать null.

Кэширование (Integer Cache): Значения от -128 до 127 кэшируются. Integer a = 100; Integer b = 100; вернет a == b как true. Но для 128 — false.

Autoboxing / Unboxing: Автоматическое преобразование. Может вызвать NullPointerException, если обёртка равна null, а вы используете её как примитив.

Вопрос: От какого класса наследуются числовые обёртки?

Ответ: От абстрактного класса java.lang.Number.

📖 Подробнее про класс Number

Number предоставляет абстрактные методы: intValue(), longValue(), floatValue(), doubleValue(), byteValue(), shortValue().

Наследники: Byte, Short, Integer, Long, Float, Double, а также BigInteger и BigDecimal.

Позволяет создавать коллекции List<Number> и единообразно вызывать doubleValue() у любого числа.

Вопрос: Какие методы есть у класса Object?

Ответ: equals(), hashCode(), toString(), getClass(), clone(), finalize(), notify(), notifyAll(), wait().

📖 Контракты Object
  • equals() / hashCode(): Если a.equals(b), то a.hashCode() == b.hashCode(). Используются в хэш-коллекциях.
  • toString(): Строковое представление. По умолчанию ClassName@HexHashCode.
  • getClass(): Возвращает Class<?> (рефлексия).
  • clone(): Создает копию (требует Cloneable).
  • wait(), notify(), notifyAll(): Синхронизация потоков.

Вопрос: Что такое иммутабельные объекты и зачем они нужны?

Ответ: Объекты, состояние которых нельзя изменить после создания (все поля final, класс final). Пример — String. Дают потокобезопасность, безопасное кэширование.

📖 Как создать и зачем

Правила:

  • Класс final.
  • Поля private final.
  • Нет сеттеров.
  • Если поле — изменяемый объект (например, Date), при создании и возврате делается глубокая копия (defensive copy).

Преимущества: Потокобезопасность (не нужны блокировки), безопасное использование в качестве ключей HashMap.

Вопрос: В чём отличие Java 11 от Java 17?

Ответ: Обе LTS-версии. Java 17 включает Records, Sealed Classes, Pattern Matching для instanceof, улучшения в GC (ZGC), новые методы в коллекциях.

📖 Подробнее про нововведения Java 17
  • Records: Лаконичные классы данных (record Point(int x, int y) {}).
  • Sealed Classes: Ограничение наследования (sealed interface Shape permits Circle, Square).
  • Pattern Matching (instanceof): if (obj instanceof String s) — переменная s сразу доступна.
  • Text Blocks (были в 15): Многострочные строки """...""".
  • Удалено: Security Manager (устарел), экспериментальный AOT и JIT компилятор Graal (перенесен в отдельный репозиторий).

Вопрос: Что такое try-with-resources? Можно ли использовать без catch?

Ответ: Да, можно. Ресурсы, объявленные в try (...), автоматически закрываются. Если исключение не перехватывается, оно пробрасывается вызывающему коду.

📖 Подробнее про AutoCloseable

Синтаксис работает с любыми классами, реализующими интерфейс java.lang.AutoCloseable (или Closeable).

Метод close() вызывается автоматически в обратном порядке объявления.

try (FileInputStream fis = new FileInputStream("file.txt")) {
    // работа с ресурсом
} catch (IOException e) {
    // обработка
}
// без catch: try (FileInputStream fis = ...) { ... }

Подавленные исключения (Suppressed Exceptions): Если исключение возникло и в блоке try, и при закрытии ресурса в close(), то исключение из close() добавляется к основному как suppressed (можно достать через e.getSuppressed()).

Вопрос: Всегда ли выполняется блок finally?

Ответ: Нет. Не выполнится, если JVM завершается (System.exit()), при фатальных ошибках (OutOfMemoryError), при прерывании потока. Также если в finally выброшено исключение, оно перекрывает исходное.

📖 Почему finally может не сработать
  • System.exit(0) — немедленно останавливает JVM.
  • Runtime.getRuntime().halt(0) — принудительная остановка.
  • Крах JVM (Segmentation fault, OutOfMemoryError).
  • Бесконечный цикл в try (до finally дело не дойдет).
  • Важно: Если в finally есть return, он перезапишет return из try и подавит исключения.

Вопрос: Что такое соль (salt) в контексте паролей?

Ответ: Случайная строка, добавляемая к паролю перед хешированием. Защищает от атак по радужным таблицам, делает одинаковые пароли разными.

📖 Безопасность паролей

Если два пользователя имеют пароль "12345", без соли их хэши будут одинаковыми. Злоумышленник, получив базу, может использовать радужные таблицы (заранее вычисленные хэши).

Соль (Salt) генерируется случайно для каждого пользователя. Хэш = Hash(Пароль + Соль). Соль хранится в открытом виде рядом с хэшем. Это делает невозможным использование предвычисленных таблиц.

Также важно использовать медленные алгоритмы (bcrypt, Argon2), а не быстрые (MD5, SHA-256).

Вопрос: Как эффективно читать большой текстовый файл?

Ответ: Использовать BufferedReader с буфером, читать построчно или блоками. Для бинарных файлов — BufferedInputStream или RandomAccessFile.

📖 Почему буферизация важна

Чтение с диска (I/O) — очень медленная операция по сравнению с памятью. Читать по 1 байту напрямую из FileInputStream — катастрофа для производительности.

BufferedReader читает сразу блок (например, 8 КБ) в память и выдает вам данные оттуда. Для бинарных данных используйте BufferedInputStream (без преобразования в символы).

RandomAccessFile позволяет прыгать по файлу (метод seek()), что полезно для чтения кусков больших файлов.

Вопрос: Что такое transient и @Transient?

Ответ: transient — модификатор Java, исключающий поле из сериализации. @Transient (JPA) — аннотация, указывающая, что поле не мапится на колонку БД.

📖 Разница контекстов
  • transient (Java): Если класс реализует Serializable, поле с этим ключевым словом не будет сохранено при сериализации (при ObjectOutputStream).
  • @Transient (javax.persistence / jakarta.persistence): Указывает ORM (Hibernate), что это поле не нужно сохранять в базу данных (оно не станет колонкой в таблице).

Вопрос: Как исключить поле из JSON-сериализации?

Ответ: Использовать @JsonIgnore (Jackson) или @JsonIgnoreProperties на уровне класса.

📖 Управление JSON в Jackson

Аннотация @JsonIgnore ставится над полем или геттером. Поле не будет ни сериализоваться (при отправке ответа клиенту), ни десериализоваться (при приеме запроса).

Если нужно скрыть только при сериализации, но принимать в запросе: @JsonProperty(access = JsonProperty.Access.WRITE_ONLY). Наоборот: READ_ONLY.

Вопрос: Что такое BigDecimal и когда его использовать?

Ответ: Класс для точных вычислений с фиксированной точностью. Используется для финансовых операций. Создавать из строки, сравнивать через compareTo, при делении указывать RoundingMode.

📖 Почему нельзя использовать double для денег

Типы float и double хранят числа в двоичном формате (IEEE 754). Многие десятичные дроби (например, 0.1) невозможно представить точно. В результате: 0.1 + 0.2 == 0.30000000000000004.

Правила работы с BigDecimal:

  • Всегда создавайте из строки: new BigDecimal("0.1"). Если использовать double (new BigDecimal(0.1)), ошибка заложится изначально.
  • Сравнивайте только через compareTo(), потому что equals() учитывает масштаб (scale): 1.0 и 1.00 не равны через equals, но равны через compareTo.
  • При делении обязательно указывайте точность и режим округления: a.divide(b, 2, RoundingMode.HALF_UP).

Коллекции

Вопрос: Основные интерфейсы коллекций в Java?

Ответ: Collection (корневой), List, Set, Queue, Map (не наследует Collection).

📖 Иерархия коллекций
  • Iterable → Collection: База для всех коллекций (кроме Map).
  • List: Упорядоченная, допускает дубликаты (ArrayList, LinkedList).
  • Set: Уникальные элементы (HashSet, TreeSet, LinkedHashSet).
  • Queue / Deque: Очереди (ArrayDeque, PriorityQueue, LinkedList).
  • Map: Ключ-значение (HashMap, TreeMap, ConcurrentHashMap). Не является Collection, но входит в Collections Framework.

Вопрос: Чем ArrayList отличается от LinkedList?

Ответ: ArrayList основан на массиве (быстрый доступ O(1), медленная вставка/удаление O(n)). LinkedList — двусвязный список (доступ O(n), вставка/удаление O(1)).

📖 Big-O и устройство

ArrayList: Внутри обычный массив. При заполнении создает новый массив в 1.5 раза больше и копирует элементы.

  • get(index) — O(1)
  • add(element) в конец — O(1) амортизированное
  • add(index, element) — O(n) (сдвиг)

LinkedList: Каждый элемент — узел (Node) со ссылками на prev и next.

  • get(index) — O(n)
  • add/remove по краям — O(1)
  • add/remove в середине — O(1) при наличии итератора, O(n) при поиске по индексу.

На практике ArrayList выигрывает почти всегда из-за кэша процессора (элементы лежат рядом в памяти).

Вопрос: Как устроена HashMap?

Ответ: На основе массива бакетов. Коллизии разрешаются цепочками. В Java 8 при длине цепочки > 8 она преобразуется в красно-чёрное дерево. При превышении load factor (0.75) происходит ресайз.

📖 Внутреннее устройство HashMap
  • Вычисление индекса: (n - 1) & hash, где n — длина массива (степень двойки), а hash перемешивается: h = key.hashCode()) ^ (h >>> 16).
  • Коллизия: Разные ключи могут дать одинаковый индекс. Они складываются в связный список.
  • Treeify: Если в бакете > 8 элементов (и массив >= 64), список превращается в дерево. Поиск ускоряется с O(n) до O(log n).
  • Load Factor (0.75): Когда заполнено 75% массива, происходит resize() — массив увеличивается вдвое, все элементы перехешируются.

Вопрос: Что будет, если использовать мутабельный объект как ключ в HashMap?

Ответ: Если изменить состояние объекта, его хеш-код изменится. HashMap не сможет найти значение по новому хешу, объект будет "потерян".

📖 Логическая утечка памяти

Вы положили ключ в бакет №5. Затем изменили поле ключа. hashCode() стал другим (например, бакет №10).

При вызове map.get(key) HashMap идет в бакет №10, не находит там ключ и возвращает null. А в бакете №5 объект остается навсегда, но мы не можем до него добраться. Это утечка памяти.

Решение: Ключи должны быть иммутабельными (String, Integer, records).

Вопрос: Можно ли поймать OutOfMemoryError при ресайзе HashMap?

Ответ: Теоретически да, если JVM не сможет выделить непрерывный участок памяти под новый массив бакетов (вдвое больше).

📖 Когда это реально

При ресайзе создается новый массив в 2 раза больше. Если в куче фрагментированная память и нет непрерывного блока нужного размера (например, для 100 млн элементов), JVM упадет с OutOfMemoryError: Java heap space.

Для предотвращения задавайте начальную емкость: new HashMap<>((int) (expectedSize / 0.75f) + 1).

Вопрос: Что такое TreeMap?

Ответ: Реализация SortedMap на основе красно-чёрного дерева. Ключи сортируются. Операции get/put/remove — O(log n).

📖 Красно-черное дерево и сортировка

TreeMap хранит элементы отсортированными по ключу (natural ordering или через Comparator).

Он реализует интерфейс NavigableMap, который дает удобные методы: firstKey(), lastKey(), headMap(), tailMap(), subMap().

Не допускает null ключи (если не передан компаратор, умеющий их обрабатывать).

Stream API

Вопрос: Какие способы создания Stream?

Ответ: Из коллекции (collection.stream()), из массива (Arrays.stream()), через Stream.of(), Stream.generate(), Stream.iterate(), Files.lines().

📖 Примеры инициализации 
// Из коллекции
List<String> list = Arrays.asList("a", "b");
Stream<String> stream1 = list.stream();

// Из массива
String[] arr = {"a", "b"};
Stream<String> stream2 = Arrays.stream(arr);

// Через Stream.of
Stream<String> stream3 = Stream.of("a", "b");

// Бесконечный поток (нужен limit)
Stream<Integer> stream4 = Stream.iterate(0, n -> n + 1).limit(10);

// Из файла
Stream<String> stream5 = Files.lines(Paths.get("file.txt"));

Вопрос: Что делает метод peek()?

Ответ: Промежуточная операция, возвращает тот же поток. Позволяет выполнить действие (Consumer) для каждого элемента, например, для логирования.

📖 Ленивые вычисления в Stream

Stream API лениво. peek не сработает, пока не будет вызвана терминальная операция (collect, count, forEach).

list.stream()
    .filter(s -> s.length() > 3)
    .peek(s -> System.out.println("Прошло фильтр: " + s)) // Ничего не выведет без терминальной операции
    .collect(Collectors.toList());

Важно: В некоторых оптимизациях JVM (например, при count()) peek может вообще не вызываться, так как элементы не запрашиваются фактически.

Вопрос: Как найти самый часто встречающийся элемент в списке с помощью Stream API?

Ответ: Сгруппировать элементы, посчитать их количество (Collectors.counting), затем найти максимум по значению.

📖 Пример кода и объяснение 
Map<Integer, Long> freq = list.stream()
    .collect(Collectors.groupingBy(n -> n, Collectors.counting()));

Optional<Map.Entry<Integer, Long>> max = freq.entrySet().stream()
    .max(Map.Entry.comparingByValue());

Integer mostFrequent = max.map(Map.Entry::getKey).orElse(null);

Альтернативный подход (без промежуточной Map):

Integer mostFrequent = list.stream()
    .collect(Collectors.collectingAndThen(
        Collectors.groupingBy(n -> n, Collectors.counting()),
        map -> map.entrySet().stream().max(Map.Entry.comparingByValue()).map(Map.Entry::getKey).orElse(null)
    ));

Вопрос: Что такое Collectors.groupingBy?

Ответ: Коллектор, группирующий элементы по ключу (функции классификатора). Результат — Map<K, List<V>> по умолчанию.

📖 Продвинутая группировка

Можно передать второй аргумент — downstream коллектор:

// Группировка строк по длине, подсчет количества
Map<Integer, Long> countByLength = words.stream()
    .collect(Collectors.groupingBy(String::length, Collectors.counting()));

// Группировка, сбор в Set
Map<Integer, Set<String>> setByLength = words.stream()
    .collect(Collectors.groupingBy(String::length, Collectors.toSet()));

Вопрос: Что такое промежуточные и терминальные операции?

Ответ: Промежуточные (filter, map, sorted, peek) возвращают Stream и ленивы. Терминальные (collect, forEach, reduce, count) запускают вычисления и закрывают поток.

📖 Правила работы со Stream
  • Поток нельзя использовать повторно после вызова терминальной операции (будет IllegalStateException).
  • Промежуточные операции могут быть объединены в пайплайн.
  • Если не вызвать терминальную операцию, ничего не произойдет (даже если есть ошибки в лямбдах).

Многопоточность

Вопрос: Что такое ThreadPool и зачем он нужен?

Ответ: Механизм управления набором потоков для выполнения задач. Позволяет переиспользовать потоки, избегая накладных расходов на их создание/уничтожение.

📖 Параметры ThreadPoolExecutor
  • corePoolSize: Базовое количество потоков, которые всегда живы.
  • maximumPoolSize: Максимальное количество потоков.
  • keepAliveTime: Время жизни лишних потоков (сверх core) без задач.
  • workQueue: Очередь задач (BlockingQueue). Если все core-потоки заняты, задачи встают сюда. Если очередь переполнена, создаются новые потоки до maximumPoolSize.
  • RejectedExecutionHandler: Что делать, если всё переполнено (AbortPolicy, CallerRunsPolicy и т.д.).

Вопрос: Какие виды пулов потоков есть в Java?

Ответ: newFixedThreadPool(n), newCachedThreadPool(), newSingleThreadExecutor(), newScheduledThreadPool(n).

📖 Разница между ними
  • Fixed: Фиксированное число потоков, бесконечная очередь (LinkedList). Задачи ждут в очереди.
  • Cached: core = 0, max = Integer.MAX_VALUE, очередь SynchronousQueue. Потоки создаются под каждую задачу и умирают через 60 сек. Хорош для коротких асинхронных задач.
  • SingleThread: 1 поток, бесконечная очередь. Гарантирует последовательное выполнение.
  • Scheduled: Позволяет выполнять задачи с задержкой или периодически (cron-подобные).

Вопрос: Что такое монитор в Java?

Ответ: Встроенный механизм блокировки, связанный с каждым объектом. Используется в synchronized блоках/методах.

📖 Как работает synchronized

У каждого объекта в Java есть заголовок (Mark Word), в котором хранится состояние монитора. Когда поток входит в synchronized(obj), он захватывает монитор этого объекта. Другие потоки, пытающиеся захватить тот же монитор, переходят в состояние BLOCKED и ждут.

В synchronized методе экземпляра монитором является this. В статическом методе — объект Class (ClassName.class).

Вопрос: Что такое потерянное обновление (lost update)?

Ответ: Две транзакции читают одну строку, затем обе обновляют её, и второе обновление перезаписывает первое.

📖 Как бороться с Lost Update

Пессимистическая блокировка: SELECT ... FOR UPDATE. База блокирует строку до конца транзакции.

Оптимистическая блокировка: Добавляем колонку version. При обновлении: UPDATE table SET val = ?, version = version + 1 WHERE id = ? AND version = ?. Если обновлено 0 строк, значит кто-то другой уже изменил запись, выбрасываем исключение и просим повторить.

Вопрос: Уровни изоляции транзакций?

Ответ: Read Uncommitted, Read Committed, Repeatable Read, Serializable.

📖 Аномалии чтения
  • Dirty Read: Чтение незакоммиченных данных (грязное чтение).
  • Non-Repeatable Read: Повторное чтение одной строки дает разные результаты (кто-то обновил и закоммитил).
  • Phantom Read: Повторный запрос диапазона выдает новые строки (кто-то сделал INSERT и закоммитил).

Уровни изоляции по возрастанию строгости: RU (допускает всё) → RC (убирает Dirty Read) → RR (убирает Non-Repeatable) → Serializable (убирает Phantom Read, полностью последовательное выполнение).

JVM и память

Вопрос: Что такое утечка памяти в Java?

Ответ: Ситуация, когда объекты больше не нужны, но на них остаются ссылки, поэтому Garbage Collector не может их удалить.

📖 Частые причины утечек
  • Статические коллекции (static Map), в которые бесконечно добавляют объекты.
  • Незакрытые ресурсы (InputStream, Connection).
  • Неверно переопределенные equals() и hashCode() (например, ключи в HashMap перестают находиться).
  • Слушатели (Listeners) или Callback-и, которые не отписываются.
  • ThreadLocal переменные без вызова remove().

Spring Framework

Вопрос: Что такое IoC и DI?

Ответ: Inversion of Control — контейнер управляет созданием и жизненным циклом объектов (бинов). Dependency Injection — внедрение зависимостей в бин через конструктор, сеттер или поле.

📖 Как это работает в Spring

IoC (Инверсия управления): Вместо того чтобы объект сам создавал свои зависимости (new MyService()), он получает их извне. Управление передается контейнеру Spring (ApplicationContext).

DI (Внедрение зависимостей): Способы передачи зависимостей:

  • Constructor Injection: Через конструктор (самый надежный, позволяет делать поля final).
  • Setter Injection: Через сеттеры (для опциональных зависимостей).
  • Field Injection: Через @Autowired прямо в поле (не рекомендуется, так как мешает тестированию).

Вопрос: Какие скоупы бинов есть в Spring?

Ответ: singleton, prototype, request, session, application, websocket, globalSession (устарел).

📖 Особенности скоупов
  • singleton (по умолчанию): Один экземпляр на весь ApplicationContext. Важно: бины должны быть stateless (без изменяемого состояния), иначе будут проблемы с потоками.
  • prototype: Новый экземпляр при каждом getBean() или инъекции. Spring не управляет уничтожением таких бинов (нужно чистить вручную или реализовывать DisposableBean).
  • request: Один бин на HTTP-запрос (только для Web).
  • session: Один бин на HTTP-сессию.
  • application: Один бин на ServletContext.
  • websocket: Один бин на WebSocket-сессию.

Вопрос: Что делает аннотация @PostConstruct?

Ответ: Метод, помеченный ею, вызывается после создания бина и внедрения всех зависимостей, но до использования.

📖 Жизненный цикл бина

Порядок вызовов:

  1. Создание экземпляра (вызов конструктора).
  2. Внедрение зависимостей (DI).
  3. Вызов метода с @PostConstruct (инициализация).
  4. Использование бина (работа приложения).
  5. Вызов метода с @PreDestroy (очистка ресурсов перед уничтожением контекста).

Начиная с Java 11, javax.annotation.PostConstruct удален из JDK и требует зависимости jakarta.annotation-api.

Вопрос: Как работает @Transactional?

Ответ: Spring создаёт прокси вокруг бина. Прокси открывает транзакцию, выполняет метод, коммитит или откатывает. Не работает на private методах и при self-invocation.

📖 Подводные камни @Transactional

Как работает: Используется Spring AOP (CGLIB или JDK Dynamic Proxy). Прокси оборачивает метод в try-catch, вызывая TransactionManager.

Почему не работает на private: CGLIB-прокси создает подкласс вашего класса. Приватные методы не наследуются, а вызовы изнутри класса идут через this, минуя прокси.

Откат (Rollback): По умолчанию откат происходит только для RuntimeException и Error. Для проверяемых (Checked) исключений отката не будет, если не указать @Transactional(rollbackFor = Exception.class).

Вопрос: Внешняя конфигурация в Spring Boot: какие способы?

Ответ: Файлы application.properties/yml, профили, переменные окружения, аргументы командной строки, Spring Cloud Config, Vault, Kubernetes ConfigMaps/Secrets.

📖 Приоритеты и профили

Spring Boot позволяет переопределять настройки без пересборки приложения. Вы можете использовать профили (application-dev.yml, application-prod.yml) и активировать их через --spring.profiles.active=prod.

Иерархия приоритетов (сверху вниз):

  1. Аргументы командной строки (--server.port=8081).
  2. Переменные окружения (Environment Variables).
  3. Профильные файлы (например, application-prod.yml).
  4. Базовый файл application.yml.

Вопрос: Что такое Spring Boot Actuator?

Ответ: Модуль для мониторинга и управления приложением: health checks, метрики, информация о среде, логи.

📖 Основные эндпоинты Actuator

Для включения добавьте зависимость spring-boot-starter-actuator.

По умолчанию доступны эндпоинты (через /actuator/*):

  • /health — состояние приложения (доступна БД, диск, кастомные health-индикаторы).
  • /info — информация о сборке (версия, git commit).
  • /metrics — метрики JVM (память, GC, потоки) и HTTP-запросов.
  • /env — переменные окружения и конфигурация (часто скрывается в продакшене).
  • /loggers — просмотр и изменение уровней логирования в рантайме.

JPA / Hibernate

Вопрос: Какие каскадные операции есть в JPA?

Ответ: CascadeType.PERSIST, MERGE, REMOVE, REFRESH, DETACH, ALL.

📖 Что означает каждый тип
  • PERSIST: При сохранении родителя сохраняются и дети.
  • MERGE: При обновлении родителя обновляются дети.
  • REMOVE: При удалении родителя удаляются дети (опасно!).
  • REFRESH: При обновлении данных родителя из БД обновляются и дети.
  • DETACH: При отсоединении родителя от сессии, дети тоже отсоединяются.
  • ALL: Включает все вышеперечисленные.

Вопрос: Что такое проблема N+1?

Ответ: При загрузке родительских сущностей и их ленивых коллекций Hibernate выполняет 1 запрос на родителей и N дополнительных запросов на каждую коллекцию.

📖 Как решать проблему N+1

Пример: 10 авторов, у каждого книги. authorRepository.findAll() делает 1 запрос. В цикле author.getBooks() делает 10 запросов.

Решения:

  • JOIN FETCH (JPQL): SELECT a FROM Author a JOIN FETCH a.books.
  • @EntityGraph: Указать над методом репозитория, какие поля грузить жадно.
  • Batch Fetching (Hibernate): @BatchSize(size = 20) над коллекцией — грузит пачками по 20.
  • DTO: Сразу выбирать только нужные данные.

Вопрос: Какие уровни кэша есть в Hibernate?

Ответ: L1 (кэш сессии, работает всегда) и L2 (кэш фабрики сессий, требует настройки и провайдера).

📖 Разница L1 и L2

L1 Cache (Session): Работает в рамках одной транзакции/сессии EntityManager. Нельзя отключить. Обеспечивает identity guarantee (один и тот же объект при повторном запросе).

L2 Cache (SessionFactory): Общий для всех сессий. Требует провайдера (Ehcache, Hazelcast) и аннотаций @Cacheable. Используется для редко меняющихся справочников.

Вопрос: Что можно использовать в качестве @Id?

Ответ: Long, Integer, String, UUID, BigInteger, составные ключи через @EmbeddedId или @IdClass.

📖 Выбор стратегии ID

Тип Long с @GeneratedValue(strategy = GenerationType.IDENTITY) — самый популярный вариант (суррогатный ключ).

UUID полезен в распределенных системах (можно сгенерировать до сохранения в БД), но занимает больше места (128 бит) и медленнее индексируется.

Составные ключи (@EmbeddedId) обычно используются только при работе с legacy-базами.

Базы данных

Вопрос: Что такое денормализация?

Ответ: Намеренное добавление избыточных данных для повышения производительности чтения, упрощения запросов или снижения количества JOIN.

📖 Примеры денормализации

В нормализованной БД (3НФ) данные без дублирования. Но чтение может требовать 5 JOIN'ов.

Денормализация:

  • Добавление вычисляемых полей (например, total_price в заказе, чтобы не суммировать позиции каждый раз).
  • Дублирование имени пользователя в таблице постов (чтобы не делать JOIN с таблицей users).
  • Использование материализованных представлений (Materialized Views).

Минус: усложняется обновление данных (нужно следить за консистентностью копий).

Вопрос: Что такое план запроса?

Ответ: Описание того, как СУБД будет выполнять запрос: какие индексы использовать, порядок соединения таблиц, стоимость операций.

📖 EXPLAIN и оптимизация

Перед запросом пишется EXPLAIN (в PostgreSQL) или EXPLAIN ANALYZE.

Вы увидите:

  • Seq Scan (Full Table Scan): Плохо для больших таблиц. Значит, индекс не используется.
  • Index Scan: Хорошо, база использует индекс.
  • Nested Loop / Hash Join / Merge Join: Как соединяются таблицы.
  • Cost (стоимость): Условные единицы затрат.

Микросервисы и распределенные системы

Вопрос: Как общаются микросервисы при потере ответа?

Ответ: Используют таймауты, повторные попытки (retry), Circuit Breaker, асинхронные сообщения через брокеры, fallback-логику.

📖 Паттерны отказоустойчивости
  • Timeout: Не ждать ответа вечно.
  • Retry: Повторная попытка с экспоненциальной задержкой (exponential backoff) и jitter (случайным разбросом), чтобы не перегрузить сервис.
  • Circuit Breaker: Если сервис падает N раз, "размыкаем цепь" — временно перестаем слать запросы, отдаем fallback.
  • Fallback: Запасной вариант (кэш, дефолтное значение).

Вопрос: Что такое теорема CAP?

Ответ: В распределённой системе при сетевом разделении (Partition) можно гарантировать только два из трёх свойств: Consistency, Availability, Partition tolerance.

📖 Выбор между CP и AP

Так как сеть может упасть (P) — от этого нельзя отказаться в распределенной системе. Поэтому выбор между C и A:

  • CP (Consistency + Partition tolerance): Если узел потерял связь с другими, он перестает отвечать на запросы, чтобы не выдать устаревшие данные. Пример: MongoDB, HBase, ZooKeeper.
  • AP (Availability + Partition tolerance): Узел продолжает отвечать, даже если данные могут быть устаревшими (Eventual Consistency). Пример: Cassandra, DynamoDB, CouchDB.

Вопрос: Что такое паттерны Outbox и Inbox?

Ответ: Паттерны для гарантированной доставки сообщений между сервисами без распределенных транзакций (2PC).

📖 Механика работы Outbox / Inbox

Проблема: Как сохранить данные в БД и одновременно отправить сообщение в Kafka? Если сделать одно, а второе упадет — система в несогласованном состоянии.

Outbox (Отправитель):

  1. В одной транзакции БД вы пишете бизнес-данные (например, Order) и событие (OrderCreated) в таблицу outbox.
  2. Фоновый процесс (Debezium) читает outbox и отправляет в брокер.
  3. После отправки запись удаляется.

Inbox (Получатель):

  1. Получаем сообщение.
  2. Сохраняем ID сообщения в таблицу inbox и обновляем бизнес-данные в одной транзакции.
  3. Если сообщение придет повторно, вставка упадет по уникальному ключу (идемпотентность).

Вопрос: Что такое HATEOAS?

Ответ: Hypermedia as the Engine of Application State — сервер возвращает в ответе ссылки на доступные действия с ресурсом.

📖 REST Level 3

Модель зрелости Ричардасона (Richardson Maturity Model) делит REST API на 4 уровня (0-3). HATEOAS — это уровень 3 (самый высокий).

Клиенту не нужно знать URL заранее. Он получает JSON с данными и блоком _links:

{
  "id": 1,
  "status": "PENDING",
  "_links": {
    "cancel": { "href": "/orders/1/cancel" },
    "pay": { "href": "/orders/1/pay" }
  }
}

Сервер сам управляет переходами состояний (State Machine).

Docker и Kubernetes

Вопрос: В чём разница между Docker и Kubernetes?

Ответ: Docker — платформа для создания и запуска контейнеров. Kubernetes — система оркестрации для управления множеством контейнеров.

📖 Что именно делает K8s
  • Self-healing: Перезапускает упавшие контейнеры.
  • Auto-scaling: Добавляет/убирает реплики контейнеров в зависимости от нагрузки (HPA).
  • Service Discovery: Дает внутренние DNS-имена контейнерам для связи друг с другом.
  • Load Balancing: Распределяет трафик между репликами.
  • Rolling Updates: Обновляет версии приложения без простоя.

Вопрос: Как искать логи в Kubernetes?

Ответ: kubectl logs <pod> для текущих логов, kubectl logs <pod> --previous для предыдущего запуска. Для централизованного сбора — ELK или Grafana Loki.

📖 Централизованное логирование

Если подов десятки, бегать с kubectl неудобно. Логи собирают агентами (Fluent Bit, Fluentd, Promtail) и отправляют в:

  • ELK / EFK: Elasticsearch (хранение/поиск), Logstash/Fluentd (сбор), Kibana (визуализация).
  • Grafana Loki: Более легковесная система, индексирует только метки (labels), а сами логи хранит сжатыми блоками. Идеально сочетается с Grafana.

Паттерны проектирования

Вопрос: Как реализовать Singleton?

Ответ: Приватный конструктор, статическое поле для экземпляра, публичный статический метод получения.

📖 Потокобезопасные реализации
  • Eager Initialization: private static final Singleton INSTANCE = new Singleton(); (создается при загрузке класса).
  • Double-Checked Locking: С volatile и synchronized (сложный, но ленивый).
  • Static Inner Class (Bill Pugh): Ленивый и потокобезопасный за счет механизма загрузки классов JVM. Рекомендуемый вариант.
  • Enum Singleton: public enum Singleton { INSTANCE; } (защищен от рефлексии и сериализации, самый надежный).

Вопрос: Зачем нужен Builder?

Ответ: Для пошагового создания объектов с большим количеством параметров, избегая перегруженных конструкторов.

📖 Проблема телескопического конструктора

Без Builder'а код выглядит так: new User("John", null, "Doe", 25, null, true). Непонятно, что значит true или null.

С Builder'ом:

User user = User.builder()
    .firstName("John")
    .lastName("Doe")
    .age(25)
    .active(true)
    .build();

Плюсы: читаемость, возможность делать объекты иммутабельными (без сеттеров).

Прочее

Вопрос: REST vs SOAP?

Ответ: REST — архитектурный стиль (HTTP, JSON, stateless). SOAP — протокол (XML, строгая типизация, WSDL).

📖 Когда что использовать
  • REST: Легче, быстрее, идеален для веб-приложений и мобильных клиентов. Использует стандартные HTTP-методы (GET, POST, PUT, DELETE).
  • SOAP: Тяжелее, но имеет встроенные стандарты безопасности (WS-Security), транзакций (WS-AtomicTransaction) и надежности (WS-ReliableMessaging). Используется в банках, enterprise-системах (например, интеграция с 1С или госуслугами).

Вопрос: Что такое Maven и какие основные команды?

Ответ: Инструмент сборки. Основные команды: mvn clean, mvn compile, mvn test, mvn package, mvn install.

📖 Жизненный цикл сборки

Maven использует концепцию жизненного цикла (build lifecycle). Выполнение команды запускает все предыдущие фазы:

  • validate — проверка проекта.
  • compile — компиляция исходников.
  • test — запуск юнит-тестов.
  • package — упаковка в JAR/WAR (в папку target).
  • verify — проверка пакета (интеграционные тесты).
  • install — установка в локальный репозиторий (~/.m2), чтобы другие проекты на этой машине могли использовать артефакт.
  • deploy — отправка в удаленный репозиторий (Nexus, Artifactory).
